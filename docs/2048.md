# 2048 可选功能

2048 源码集中在 `app/features/game2048/`。默认只注册轻量工具声明，批准 `play_2048` 调用后才读取页面脚本、加载游戏运行代码；本地搜索动态库仅在启用搜索辅助时加载。

## 启用与关闭

正常启动命令不变，`uv run python main.py`。未配置开关时，2048 默认按需可用。

暂时专注其他功能时，可以仅对本次启动关闭：

```bash
MIE_ENABLE_2048=0 uv run python main.py
```

也可以在本地 `.env` 设置 `MIE_ENABLE_2048=0` 并重启。关闭后不会注册 `play_2048`、其审批项。恢复 `MIE_ENABLE_2048=1` 并重启后，再向小咩提出游戏要求即可。开关只接受 `1` 为启用，其余值视为关闭。

环境变量优先于 `.env`。这次没有改动你的 `.env`。开关是功能配置，不是 Shell 沙箱；保留的报告、存档、经验和本地算法缓存不会因关闭而删除。

## 玩一轮

重启小咩后，输入：**“用 Jev 在 play2048.co 玩 2048，最多 50 步，最多 120 秒。”**

小咩调用 `play_2048(max_steps=50, max_seconds=120)`。批准这一次工具调用，即授权本次限定范围内的浏览器动作及最多 50 次 Jev API 请求；循环内不再逐步经过主聊天模型或弹出工具审批。普通 `jev_choose`、Shell 和其他工具的审批保持原有配置。

- 前置条件：本机 `bsk` 可用，BrowserSkill daemon 正在运行，且只有一个已连接的浏览器；仍使用本项目的 `TYPESAFE_API_KEY`。连接复用使用已在依赖树中的 `httpx==0.28.1`，现显式声明为直接依赖。
- 工具创建专用浏览器会话，打开固定的 `https://play2048.co/`，继续网站已保存的棋盘；不借用用户标签页，不使用道具。用户授权后可设置 `new_game=true`，仅在验证真实 `gameOver` 后点击页面的 Play Again/New Game，验证新棋盘和零分零步。
- 网站目前用 Canvas 显示，但已加载的前端模块公开了可订阅的游戏状态。插件按接口特征定位它，只读取棋盘、分数和步数，不修改游戏状态。网站更新或字段不完整时停止，不能靠猜测继续。
- 每一步：读取棋盘 → 在本地计算合法滑动结果 → （安全方向过滤）→ Jev 选择方向 → 核对棋盘未被手动改动 → 触发页面方向键事件 → 验证合并、得分与新增的一个方块。默认方向来自 Jev；显式开启搜索辅助时见下文。通过游戏原有按键处理逻辑移动，不直接调用游戏的 move 或写入棋盘。
- 安全方向过滤：对每个候选方向，本地确定性推演「滑行 + 在**每个**空位分别生成 2 和 4」的全部结果，统计每个结果是否还存在合法动作。只要某个方向在任何生成情况下都不会立即满盘死锁，就只把这类「安全方向」和 `stop` 提供给 Jev；一个安全方向都没有时，如实退回全部能移动的方向 + `stop`，不编造安全选项。报告逐步记录 `safe_directions` 与 `risky_directions`，便于复盘「是否存在安全备选」。
- 经验接入：每轮从 `workspace/memories/2048-lessons.md` 正文抽取各条「下次具体如何选择」的首段，拼成简短策略摘要随棋盘发给 Jev。报告里的 `lessons_summary` 就是实际发送的同一字符串（同源派生），`lessons_loaded` / `lessons_sent_to_jev` 记录实际是否传入；文件缺失或无可执行条目时退化为无经验提示，不编造经验。
- 核对、按键事件、读回合并成一次 BrowserSkill `evaluate`，避免逐步切换浏览器焦点；每局复用同一 HTTP 客户端。专用页仅关闭 BrowserSkill 装饰边框的呼吸动画，保留状态提示、停止按钮、输入保护和浏览器调试提示，不修改全局设置。
- 步数范围 1–200，时间范围 1–300 秒，先到者停止；到达 2048、无法移动、Jev 弃权或错误、读取或结果验证失败也停止，不自动重试。截图和会话清理可能使返回时间略超出游戏时间上限。
- TUI 按 `Esc` 停止后续动作。已发送的 HTTP 请求可能继续完成，但不会据此再按键。同步 `--plain` 入口也可使用此工具。
- 完成时等待 0.3 秒让方块动画收尾，保存最终截图和逐步 JSON 报告到 `workspace/reports/2048/`。默认关闭本次会话；`keep_page_open=true` 保留原页，返回一次性的 `continuation_id`，续玩时传回并继续设置保留，可避免每轮重建窗口。句柄只在当前进程有效，重启后须重新读取网站存档；不能保证网站恢复终局。保留位置为 Agent Window，工具不会声称已归还普通窗口。逐步决策不固定等待动画。报告记录每步棋盘、Jev 选择/概率/置信度/用量、读取/决策/执行验证耗时；不记录密钥。返回的 `steps` 只计算已验证的动作。

这是让 Jev 连续做决策的实验，不保证到达 2048。速度应看报告里的端到端耗时和 `jev_seconds`，不要拿主聊天模型的 token/s 当作游戏速度。

## Jev + 本地搜索辅助

首次构建：`.venv/bin/python -m app.features.game2048.solver --build`，需要本机 C++11 编译器。
算法核心为 MIT 协议的 [nneonneo/2048-ai](https://github.com/nneonneo/2048-ai)，
来源版本和改动记录见 `app/features/game2048/native/README.md`；不安装上游浏览器控制代码。

用户授权算法辅助后，调用 `play_2048(max_steps=200, max_seconds=300, search_assist=true, keep_page_open=true)`。
Jev 与本地 Expectimax 并行工作，搜索预算每步 80 毫秒，只比较同一已完成深度的候选分数；
若搜索分数更优则校正 Jev 的方向，平分时保留 Jev。计算只在本地模拟棋盘，不读取网站随机种子。
搜索采用标准 90% 生成 2 / 10% 生成 4 的假设，启发式分数不代表胜率。
报告同时保留 `result`（原始 Jev 返回）、`search`、`jev_direction`、`executed_direction`、
`overridden`、`decision_seconds`；因此应称为“Jev + 搜索辅助通关”，不能称为 Jev 独立通关。
Jev 弃权/报错、搜索失败、读取/验证失败仍停止，不用算法绕过这些停止条件。
只有真实棋盘含 2048 才报告成功；仅有网站 `gameWon` 标记不够。

可复制给小咩：

> 用 Jev + 本地搜索辅助玩 2048，允许算法校正方向。每轮调用 play_2048，max_steps=200、max_seconds=300、search_assist=true、keep_page_open=true；达到单轮限制就携带 continuation_id 继续同一页。总共最多 2000 步及 2000 次 Jev 请求、30 分钟、3 局。当前若明确 game_over，允许 new_game=true 点击网站按钮；不要提前重开。出现真实 2048 就停止并保留页面，错误或 Jev 弃权也立即停。报告实际方向、校正次数、分数、总步数、耗时及报告路径。

离线验证：`.venv/bin/python -m unittest discover -s tests -t . -q`；
固定种子棋力抽查：`.venv/bin/python -m tests.benchmark_2048`（不调用 Jev、不操作网站）。

## 按需读取游戏规则

完整规则保存在 `workspace/skills/game2048/SKILL.md`，主 Agent 通过已有的 Skills 配置发现其名称、适用描述和路径。用户要求实际玩或续玩时，模型应先通过 `read_file` 读取 `/skills/game2048/SKILL.md`，再调用 `play_2048`。讨论游戏原理不会要求启动游戏。

主系统提示词不再拼接 2048 规则；启用时只注册简短的工具入口。Skill 匹配由模型判断，不是关键词触发器。关闭功能后 Skill 文件仍可发现，但工具不注册，不能绕过开关；审批通过后才加载游戏实现的行为保持不变。
