# MIE · 小咩助手

小咩助手（MIE）是使用 Deep Agents 逐章搭建的个人研究助手，也是贯穿课程的学习项目。

最终目标：用户输入主题，小咩展示研究过程，生成带来源的报告，并保存供以后查看；先实现终端连续对话与工具调用展示，再接入网页。学习者能解释并修改其中的主要流程。每章先做课程练习，再判断哪些能力适合接入小咩，不强行用齐所有功能。

课程关联记录见 [课程练习说明](https://github.com/Mie-coder/deepagent-learning/blob/main/exercises/README.md#整门课的个人实践目标)，这只是学习参考链接，不是运行依赖。

当前已接入 DeepSeek、Tavily 搜索和北京时间工具，可以在终端连续聊天。新增 Textual 界面用于展示流式回答、可展开的工具记录和运行用量。网页、研究资料持久化仍待后续课程接入。核心聊天代码由学习者在指导下编写，时间工具和 TUI 由助手实现；运行成功不自动等于独立掌握。

## 从这里开始

在小咩项目目录（与本项目的 `pyproject.toml` 同级）的 VS Code 终端运行：

```bash
uv run python main.py
```

预期先启动本机研究服务，再进入“MIE · 小咩助手”聊天界面；无需手动运行 langgraph dev。服务使用随机本机端口，不占用课程实验的 2024。启动本身不请求模型，发送问题后会调用实际模型，搜索任务还会调用 Tavily。项目有自己的 `pyproject.toml`、`uv.lock`、`.venv` 和 `.env`，不使用课程模板的虚拟环境或运行配置。初次安装或迁移到其他电脑时执行 `uv sync --locked`。

需要使用简单的 `while` / `ainvoke` 聊天循环时，可运行 `uv run python main.py --plain`。

### 终端操作

- `Enter` 发送，`Ctrl+J` 换行；多行粘贴不会自动发送。
- 连续的 `ls`、`read_file`、`glob`、`grep` 操作默认合并成一条折叠摘要（例如 `List 3 · Read 4 · 7 completed`）；展开后可查看每次调用。出现正文或其他工具时开始新的分组，失败与停止会在摘要中标明。
- 点击工具记录，或用 `Shift+Tab` 移动焦点后按 `Enter` 展开参数和结果。
- 默认“逐步审核”；`Tab` 切换“本轮自动”，再次按下切回。输入问题前、运行中和等待审批时都可切换，底部持续显示当前模式。
- 待审批时点击批准/拒绝，或按 `Ctrl+Y` / `Ctrl+N`；默认焦点在拒绝按钮。
- “本轮自动”覆盖本轮 Agent 配置中需要审批的工具，包括 Shell 和文件修改。完成、失败或停止后恢复逐步审核；`--plain` 仍逐次询问，不支持 Tab 切换。
- 切回审核只影响尚未批准的请求，不能撤回已批准的一批操作。自动模式不是沙箱，也不代替浏览器扩展自身的确认。
- 鼠标滚轮或 `PageUp` / `PageDown` 翻阅；向上翻时不会强制回到底部，`Ctrl+End` 回到最新。
- `Esc` 只停止当前回复，后台研究继续。要取消研究，请发送“取消刚才的后台研究”。取消工具会核对服务端 run 的终态；已经发出的外部搜索请求不承诺撤销。
- `/help` 查看帮助；`/clear` 清空聊天和计划展示，但保留后台研究记录；`/exit` 或 `Ctrl+Q` 退出并停止本应用启动的研究服务。任务不会跨应用重启恢复。
- 失败时保留已显示的文字，并将原始需求和明确的失败说明加入后续模型上下文；中间资料及未完成工具调用不加入历史。可以要求重新执行，但这不是断点恢复。主动停止的一轮仍不加入历史，之前成功的对话保留。连接错误展示底层异常类型与诊断提示，不显示原始请求或凭证。
- 对话仅保存在当前进程中，退出后不保留；普通工具展开详情较长时截取前 8000 字符，只影响显示。`task` 详情保留 `subagent_type`、`description` 等英文字段名，任务描述正常换行，`content` 显示完整 Markdown 正文，`Raw data` 折叠项保留原始参数和结果。
- 多步骤研究可展示任务计划：待开始、进行中、已完成。清单跟随 `write_todos` 成功返回的状态更新；简单问答无需列计划。每轮有自己的计划展示，旧计划保留在聊天记录中，`/clear` 一并清空。
- 回答结束不代表所有任务完成；停止或失败时保留最后状态并标注“本轮未完成”。任务清单未接入跨进程恢复。`--plain` 同样启用规划工具，但仍只打印最终回答。

底部显示主 Agent 本轮总耗时、接口返回的输出 token 数和平均 `token/s`；后台研究员的模型用量不在这个本轮计数中。速度按“输出 token ÷ 模型调用耗时之和”计算，包含首字等待和工具参数生成，不包含搜索等待时间。用量一般在每次模型调用结束时返回，因此生成中不会用字符数冒充实时 token 数；未返回用量时显示“未提供”，部分调用尚未回报时标记“部分”。它是本客户端观察到的平均速度，不是服务端纯解码速度。

打开上一级的 `deepagents-learning.code-workspace`，可在 VS Code 同一窗口的资源管理器中同时查看课程项目与小咩。右键小咩目录选择“在集成终端中打开”，即可在正确目录运行。

## 后台研究

第一版每段会话最多一个活跃后台研究，进度和结果按需查询，不自动通知。可以依次发送：

1. “后台研究 LangGraph 的 thread 和 run 区别，保留官方来源；启动后先返回。”
2. “研究继续，先解释一下什么是接口约定。”
3. “给刚才的研究追加要求：只看官方文档。”
4. “查询刚才研究的最新状态，完成后展示结果和来源。”

不再需要时发送“取消刚才的后台研究”。工具记录会区分已启动、运行中、已完成和已取消；启动工具完成不表示研究完成。研究员只有搜索能力，不继承主助手的 Shell、文件写入或游戏工具。详见 [实现与验证说明](docs/background-research.md)。

## 配置来源

### Jev 决策工具

在本地 `.env` 中增加 `TYPESAFE_API_KEY=你的密钥`，然后重启小咩。
密钥在 [TypeSafe 控制台](https://console.typesafe.ai) 获取，无需更换 DeepSeek 主模型或安装新依赖。
`app/jev.py` 调用 [官方 Choice API](https://docs.typesafe.ai/api)，固定模型 `jev-latest`。

小咩通过 `jev_choose(state, question, choices)` 发送文字状态和备选项，获得 `choice`、`probabilities`、`confidence` 和 API 用量。
工具默认等待批准；Tab 开启本轮自动后自动批准。此调用会向 TypeSafe 发送传入的状态，缺少密钥、网络失败或响应不合法时返回 `ok=false`，不自动重试。
Jev 用量显示在工具结果中，不计入底部主聊天模型的 token/s。

可先测试：“请调用 Jev：状态是当前任务需要停止，选项是 continue 和 stop，判断应选择哪一个。不要操作浏览器。”

浏览器协作流程：BrowserSkill 读取页面 → 小咩把已确认的文字状态交给 Jev → BrowserSkill 执行动作 → 重新读取验证。
[Jev 当前只支持文本](https://docs.typesafe.ai/concepts/state)，不能读取截图或截图路径。通用 `jev_choose` 不识别 Canvas；专用 2048 插件通过读取页面游戏状态提供真实 4×4 棋盘。通用 Jev 工具接入 Choice，不含视觉模型；2048 的可选本地搜索另见功能说明，不能保证每局获胜。

### 可选的 2048 功能

2048 已集中到 `app/features/game2048/`。默认保留轻量的 `play_2048` 工具入口，批准调用后才加载游戏实现，普通聊天不读取游戏脚本或加载本地搜索。

要完全关闭该功能，在本地 `.env` 设置 `MIE_ENABLE_2048=0` 并重启；恢复为 `1` 后重新启动即可。也可以只对一次启动关闭：

```bash
MIE_ENABLE_2048=0 uv run python main.py
```

关闭时游戏工具、对应审批项与专用提示词一同移除，其他工具仍可使用。游戏规则、构建命令、继续/保留页面方法和历史验收记录见 [2048 功能说明](docs/2048.md)。

运行 `uv run python -m unittest discover -s tests -t . -v` 做离线验收；HTTP 被替换为测试响应，不消耗真实接口额度。完成配置后仍需真实 API 验证。

入口只加载本项目的 `.env`；终端已设置的同名环境变量优先。迁移时仅把已有模型、搜索和追踪相关配置复制到本地 `.env`，之后两边独立维护；真实 Key 不输出、不提交。新环境可复制 `.env.example` 为 `.env` 后填写。

LangSmith 项目名默认设为 `mie-assistant`，可在本目录 `.env` 或终端环境变量中配置。实际运行 Agent 且启用追踪时才会产生 Trace；界面用量来自模型事件，与是否启用 LangSmith 无关。

## 本地资料与版本管理

源码、测试、`docs/`、`pyproject.toml`、`uv.lock`、`.env.example` 和 `.gitignore` 适合纳入版本管理。`app/features/game2048/native/` 的源码、LICENSE 与来源说明必须一起保留；编译出的本机动态库留在缓存目录。

`.env`、虚拟环境、Python 缓存以及 `workspace/` 内的个人记忆、运行记录、截图和实验产物留在本地。`workspace/.gitignore` 已忽略该目录的内容，只保留忽略规则文件。正式报告和公众号文章没有迁移；散落的历史 2048 文件已归入 `workspace/archive/2048/2026-09-21/`，可按其中的 `manifest.json` 查找原路径。

新电脑检出源码后，执行 `uv sync --locked`，复制 `.env.example` 为本地 `.env` 并填写自己的配置。启动时会建立 `workspace/`；个人偏好文件 `workspace/memories/profile.md` 需要自行创建或从自己的备份恢复，不从代码仓库获取。

浏览器能力另依赖 [BrowserSkill](https://github.com/Tencent/BrowserSkill) 的 CLI、浏览器连接和使用说明。按上游文档安装配置，将其 `SKILL.md` 安装到本机 `workspace/skills/browser-skill/SKILL.md`，通过 `bsk status --json` 检查连接。Git 不会自动携带当前电脑的 Skill、浏览器会话或登录状态。只做普通聊天和研究时不必安装游戏的本地算法；搜索辅助的构建方式见 [2048 说明](docs/2048.md)。

新功能的专用实现放在 `app/features/<功能名>/`，详细使用说明放在 `docs/`；通用 Jev、搜索、界面和审批保持独立。仅在 `app/agent.py` 组装启用的工具与规则，不把单个实验的完整指令持续塞入主助手提示词。

## 第一版的数据流

当前流程：

```text
输入问题 → Agent 决定是否查时间或搜索 → 界面展示执行事件和回答 → 保留本次进程内的对话
```

后续再加入第三章的“让 Agent 保存研究笔记、按需读回”。Agent 文件工具与 Python 直接保存报告是两种行为，验收时分别观察。

## 界面验证与下一步

运行 `uv run python -m unittest tests.test_tui tests.test_approval_tui -v` 做离线回归；不会加载 `.env`，不会发出模型或搜索请求。检查流式显示、多轮上下文、工具详情、错误恢复、停止、中文输入、窄窗口、token/s 计算和审批模式；真实 Deep Agents 图测试使用本地预设模型。

TUI 在每轮内部使用同一个检查点线程恢复审批，收尾时删除该线程。下一轮携带此前成功对话和独立后台任务账本重新开始，避免恢复已取消的命令；工具回执在主回复完成前登记，所以 Esc、失败和 /clear 不会丢掉后台任务 ID。这不提供重启后的会话恢复。

真实验收：启动后先问“今天星期几”，查看时间工具记录；再搜索一个研究问题，展开来源并观察底部用量。中文输入法、终端复制行为和真实接口返回的速度需要在实际终端中体验。

最终还要由学习者独立修改一个研究需求，解释从请求到报告的数据流，并定位一次失败，才能把“代码可运行”推进到“自己会搭建”。
